# школо! — english, но по кайфу

Игровая образовательная платформа для изучения английского языка.

## Технологии

- React 19 + TypeScript + Vite
- Tailwind CSS
- Supabase Auth
- Vite PWA

## Запуск

```bash
npm install
npm run dev
```

Production-сборка:

```bash
npm run build
```

## Авторизация

- Регистрация с подтверждением email.
- Подтверждение email кодом из письма.
- Повторная отправка кода с таймером.
- Вход по email и паролю.
- Восстановление пароля по коду из email.
- Подтверждение recovery-кода через `verifyOtp({ type: 'recovery' })`.
- Сохранение и автоматическое восстановление сессии.

Supabase Auth поддерживает email OTP длиной от 6 до 10 цифр. Интерфейс принимает код любой поддерживаемой длины и передаёт его в `verifyOtp` полностью, поэтому настройку длины OTP можно менять в Supabase без изменения клиентского кода.

В шаблонах Supabase **Confirm signup** и **Reset Password** нужно выводить `{{ .Token }}`. Если в шаблоне оставить только `{{ .ConfirmationURL }}`, письмо будет содержать ссылку вместо кода.

Для подключения другого Supabase-проекта задайте переменные окружения:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

В клиентский код и репозиторий нельзя добавлять `service_role`, secret key, пароль базы данных или connection string.

## Контент

- 8 уроков и 48 заданий.
- 6 типов заданий: выбор ответа, ввод, верно/неверно, пары, картинки и аудио.
- Последовательное открытие уровней.
- XP, монеты, кристаллы, магазин, рейтинг, класс и профиль.

## Школьные страты и запуск базы

Перед публикацией этой версии примените в SQL Editor нужного проекта Supabase файл
`supabase/migrations/202611260001_school.sql` целиком один раз. Миграция выполняется транзакцией.
Она создаёт закрытую схему с RLS, профили для уже подтверждённых аккаунтов и триггер
для последующих подтверждений email. Старые общие ключи игрового прогресса в браузере
игнорируются. Регистрация и восстановление пароля используют прежний email OTP.

Первого администратора назначает владелец проекта. Скопируйте UUID подтверждённого
пользователя из Authentication → Users и выполните в SQL Editor:

```sql
insert into school_private.admins (id)
values ('UUID-подтверждённого-аккаунта'::uuid)
on conflict do nothing;
```

Для снятия роли удалите строку этого UUID из `school_private.admins`. После обновления
страницы администратору доступно **Профиль → Настройки → Администрирование**.
Роль проверяется в базе при каждой административной операции. Публичные RPC
доступны только авторизованным пользователям. Прямого клиентского доступа к таблицам нет.

Ученики начинают без страты. Администратор назначает 1, 2 или 2Б, переводит между
стратами, видит успеваемость, выгружает отфильтрованный список в CSV, публикует
задания, архивирует и восстанавливает их. Ученик видит участников и активные
задания своей страты. Для сдачи требуется завершить указанный урок после публикации.
Уроки открываются по порядку. Дни занятий и сроки считаются по Москве.

Завершения и покупки хранятся в PostgreSQL. Сервер проверяет ответы, порядок уроков,
стоимость покупки и баланс. Повтор запроса с тем же идентификатором попытки не
начисляет награду дважды. Новый проход урока приносит новую награду. При изменении
ответов в `src/lessons.ts` или цен в `src/data.ts` обновите соответствующий серверный
справочник новой миграцией. Подключение использует прежний публичный ключ Supabase.
